# PRD: Dota 2 Assistant Telegram Bot

**Версия:** 1.0
**Дата:** 27 февраля 2026
**Статус:** Draft

---

## 1. Обзор продукта и цели

### 1.1 Описание
Telegram-бот — персональный ассистент для игроков Dota 2, который помогает выбирать героев, подбирать билды, анализировать матчи и отслеживать прогресс. По сути — Pro Tracker + Dotabuff внутри Telegram с AI-powered аналитикой.

### 1.2 Ключевые цели
- Помогать игрокам принимать лучшие решения на этапе драфта на основе мета-данных и личной статистики
- Предоставлять актуальные билды (items + skills) с учётом текущего патча и состава команд
- Давать осмысленный анализ матчей с персонализированными советами
- Отслеживать прогресс игрока (MMR, винрейт, динамика)

### 1.3 Ключевые метрики успеха
- Количество активных пользователей (DAU/MAU)
- Конверсия в подписку
- Retention rate (7-day, 30-day)
- Точность распознавания героев на скриншотах (target: >95%)
- Среднее время ответа бота (<3 сек для текстовых запросов, <10 сек для анализа изображений)

---

## 2. Целевая аудитория

### 2.1 Основная аудитория
Игроки Dota 2 всех уровней (от 1k до 7k+ MMR), которые хотят:
- Оптимизировать свои пики на основе данных
- Следить за метой и актуальными билдами
- Анализировать свои матчи и находить точки роста

### 2.2 Требования к пользователю
- Аккаунт в Telegram
- Открытый профиль в Steam/Dota 2 (обязательно для работы бота)
- Steam ID или ссылка на профиль для привязки

### 2.3 Язык
- Русский (единственный поддерживаемый язык в v1)

## 3. Основные функции и функциональность

### 3.1 Онбординг и привязка аккаунта

**Описание:** При первом запуске бот проводит пользователя через вводные вопросы и привязывает Steam-аккаунт.

**Флоу:**
1. Пользователь запускает бота → приветственное сообщение
2. Запрос Steam ID или ссылки на профиль
3. Валидация через OpenDota API (проверка что профиль открыт)
4. Запрос текущего MMR (ввод вручную)
5. Запрос основной роли (1-5 позиция)
6. Создание профиля → главное меню

**Acceptance Criteria:**
- Бот принимает Steam ID (числовой), ссылку вида `steamcommunity.com/id/...` и `steamcommunity.com/profiles/...`
- Если профиль закрыт — информативное сообщение с инструкцией как открыть
- После привязки бот подтверждает никнейм из Steam для верификации
- Данные сохраняются в Supabase

### 3.2 Анализ драфта по скриншоту (Подписка)

**Описание:** Пользователь отправляет скриншот экрана драфта, бот распознаёт героев и рекомендует лучший пик.

**Флоу:**
1. Пользователь отправляет фото/скриншот драфта
2. LLM (GPT-4o-mini или Claude) распознаёт:
   - Героев команды союзников
   - Героев команды противника
   - Роль пользователя (по надписи на экране, если видна; иначе из профиля)
3. Бот запрашивает мета-данные из Stratz API
4. Бот рекомендует 3-5 лучших героев с учётом:
   - Контрпиков к вражеской команде
   - Синергии с союзниками
   - Текущей меты (винрейт на данном ранге)
   - Личного винрейта пользователя на этих героях (OpenDota)
5. Краткое пояснение почему каждый герой хорош в данной ситуации
6. При выборе героя — сразу выдаёт item build и skill build

**Acceptance Criteria:**
- Поддержка полного скриншота экрана, обрезанного фрагмента и фото экрана
- Распознавание команды (союзники/враги) и ролей
- Ответ в течение 10 секунд
- Если LLM не уверен в распознавании — запрос уточнения у пользователя
- Каждая рекомендация героя содержит: имя, винрейт в мете, личный винрейт, краткое пояснение

**Технические соображения:**
- Промпт для LLM должен содержать список всех героев Dota 2 для точного маппинга
- Нужна обработка edge-cases: бан-фаза, неполный драфт, плохое качество фото
- Стоимость одного запроса к GPT-4o-mini с изображением ~$0.01-0.03

### 3.3 Рекомендация героев по тексту (Бесплатно)

**Описание:** Пользователь указывает роль — бот выдаёт топ героев текущей меты для этой роли.

**Флоу:**
1. Пользователь выбирает роль (кнопки: Carry / Mid / Offlane / Soft Support / Hard Support)
2. Бот запрашивает Stratz API — топ героев по винрейту для данной роли и ранга пользователя
3. Выводит список из 5-10 героев с:
   - Винрейт в мете
   - Личный винрейт пользователя
   - Краткое пояснение почему герой сейчас силён

**Acceptance Criteria:**
- Данные фильтруются по MMR-брекету пользователя
- Героев можно выбрать для получения билда
- Ответ в течение 3 секунд

### 3.4 Билд на героя (Бесплатно)

**Описание:** Пользователь пишет имя героя и роль (или выбирает из рекомендаций) — бот выдаёт оптимальный билд.

**Флоу:**
1. Пользователь вводит героя (текстом или выбирает кнопкой)
2. Бот запрашивает Stratz API — лучший билд по винрейту для данного ранга
3. Выводит:
   - **Стартовые предметы**
   - **Core items** (порядок покупки)
   - **Ситуативные предметы** с пояснением когда брать (например, BKB если у врагов много контроля)
   - **Порядок прокачки скиллов** (1-18)
   - **Ключевые таланты**

**Acceptance Criteria:**
- Один лучший билд по мете (не множественные варианты)
- Ситуативные предметы адаптированы под вражеский пик (если известен из контекста драфта)
- Поддержка ввода героя на русском и английском ("Антимаг" и "Anti-Mage")

### 3.5 Разбор последнего матча

**Базовый разбор (Бесплатно):**
Вывод ключевых метрик в зависимости от роли:

| Метрика | Carry | Mid | Offlane | Soft Sup | Hard Sup |
|---|---|---|---|---|---|
| KDA | ✅ | ✅ | ✅ | ✅ | ✅ |
| GPM | ✅ | ✅ | ✅ | — | — |
| XPM | ✅ | ✅ | ✅ | — | — |
| Урон по героям | ✅ | ✅ | ✅ | ✅ | — |
| Полученный урон | — | — | ✅ | — | — |
| Kill Participation % | ✅ | ✅ | ✅ | ✅ | ✅ |
| Варды поставлены | — | — | — | ✅ | ✅ |
| Варды уничтожены | — | — | — | ✅ | ✅ |
| Сравнение с медианой ранга | ✅ | ✅ | ✅ | ✅ | ✅ |

**Расширенный разбор с LLM-советом (Подписка):**
- Всё из базового разбора
- Текстовое саммари игры на основе статов
- Персонализированный совет от LLM (что улучшить, на что обратить внимание)

**Acceptance Criteria:**
- Данные берутся из OpenDota API по последнему матчу
- Роль определяется автоматически по данным матча (lane role)
- Сравнение с медианой — для данного героя на данном ранге
- LLM-совет релевантен роли и учитывает контекст матча (длительность, состав команд, результат)

### 3.6 Профиль и статистика (Бесплатно)

**Описание:** Личный профиль пользователя с ключевой статистикой.

**Данные профиля:**
- Текущий MMR и ранговая медаль
- Общий винрейт
- Топ-5 героев по количеству игр (с винрейтом)
- Динамика MMR (график за последние 30 дней)
- Винрейт за последние 7 / 30 дней
- Серия побед/поражений

**Обновление MMR:**
- Автоматическая проверка через OpenDota API раз в день
- Обновление по запросу пользователя (кнопка "Обновить MMR")
- Ручной ввод MMR, если API не возвращает актуальные данные

**Acceptance Criteria:**
- Данные кэшируются в Supabase, обновляются при запросе
- Динамика MMR хранится как time-series в базе
- Профиль отображается компактно, без перегрузки данными

### 3.7 Уведомления

**Новый патч:**
- Отслеживание обновлений Dota 2 (через Stratz API или парсинг новостей)
- При выходе нового патча — уведомление всем пользователям
- Краткая сводка: ключевые изменения героев, сдвиги в мете

**Еженедельная статистика:**
- Раз в неделю (настраиваемый день) — персональная сводка:
  - Матчей за неделю
  - Винрейт за неделю
  - Изменение MMR
  - Лучший / худший герой недели
  - Краткий совет на основе трендов

**Acceptance Criteria:**
- Пользователь может отключить уведомления
- Уведомления о патчах отправляются в течение 24 часов после выхода патча
- Еженедельная статистика отправляется в фиксированное время

## 4. Техническая архитектура

### 4.1 Стек технологий

| Компонент | Технология | Обоснование |
|---|---|---|
| Бот-фреймворк | **aiogram 3.x** | Асинхронный, мощная система хендлеров, FSM для диалогов |
| Язык | **Python 3.11+** | Нативная поддержка aiogram, удобство работы с API |
| База данных | **Supabase (PostgreSQL)** | Managed PostgreSQL, встроенный REST API, real-time |
| Мета-данные | **Stratz API (GraphQL)** | Детальные данные по мете, билдам, винрейтам по рангам |
| Личная статистика | **OpenDota API (REST)** | Бесплатный, данные матчей и игроков |
| Vision AI | **GPT-4o-mini или Claude API** | Распознавание скриншотов драфта |
| LLM для советов | **GPT-4o-mini или Claude API** | Генерация саммари и советов по матчам |
| Кэширование | **Redis** (опционально) | Кэш мета-данных, rate limiting |
| Хостинг | **VPS / Cloud** | Для запуска polling/webhook |
| Task scheduler | **APScheduler / Celery** | Ежедневное обновление MMR, еженедельные отчёты, отслеживание патчей |

## 5. Навигация и UX

### 5.1 Главное меню (Reply-клавиатура)
```
┌─────────────────┬─────────────────┐
│ 🎯 Анализ драфта│ 🦸 Герои меты   │
├─────────────────┼─────────────────┤
│ 📊 Разбор матча │ 🗡 Билд героя   │
├─────────────────┼─────────────────┤
│ 👤 Мой профиль  │ ⚙️ Настройки    │
└─────────────────┴─────────────────┘
```

### 5.2 Текстовые команды
- `/start` — Онбординг / главное меню
- `/draft` — Анализ драфта (отправить скриншот)
- `/meta [роль]` — Топ героев меты для роли
- `/build [герой]` — Билд на героя
- `/lastmatch` — Разбор последнего матча
- `/profile` — Мой профиль и статистика
- `/settings` — Настройки (уведомления, обновить MMR, сменить роль)
- `/help` — Справка

### 5.3 Принципы UX
- Ответы компактные, без лишнего текста — игрокам нужна информация быстро (часто прямо во время драфта)
- Inline-кнопки для навигации внутри функций (выбор героя → показать билд)
- Поддержка ввода на русском и английском для имён героев
- Эмодзи для визуального разделения секций в сообщениях

## 6. Соображения по безопасности

- **API ключи** хранятся в переменных окружения, не в коде
- **Rate limiting** на уровне бота — защита от злоупотреблений
- **Валидация входных данных** — Steam ID, текстовые запросы
- **Supabase RLS** (Row Level Security) — пользователь видит только свои данные
- **Telegram Bot Token** — хранится безопасно, webhook с валидацией
- **Ограничение размера изображений** — максимум 10MB для скриншотов
- **Логирование без PII** — не логировать Telegram ID и Steam ID в открытом виде

## 8. Потенциальные проблемы и решения

| Проблема | Решение |
|---|---|
| **Закрытый профиль Steam** | Информативное сообщение с пошаговой инструкцией. Периодическая проверка доступности. |
| **LLM неправильно распознаёт героев** | Промпт с полным списком героев + подтверждение от пользователя при низкой уверенности. Fallback: ручной ввод. |
| **Задержки API (Stratz/OpenDota)** | Кэширование мета-данных (обновление раз в час). Graceful degradation при недоступности. |
| **Стоимость LLM при масштабировании** | Чёткое разделение free/premium. Кэширование результатов для похожих драфтов. Оптимизация промптов. |
| **Обновление данных при новом патче** | Автоматический сброс кэша мета-данных. Мониторинг Stratz на изменения версии. |
| **Фото плохого качества** | LLM обычно справляется, но при неудаче — предложить отправить текстом или более чёткое фото. |
| **Rate limits API** | OpenDota: 60 req/min (бесплатно), Stratz: зависит от плана. Реализовать очередь запросов и rate limiter. |
